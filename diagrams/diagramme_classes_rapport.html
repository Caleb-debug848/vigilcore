1. Diagramme de classes

Le diagramme de classes représente la structure statique du système VigilCore en montrant les classes, leurs attributs, leurs méthodes et les relations qui les unissent. Le diagramme de classe met en évidence d'éventuelles relations entre ces classes. Le diagramme de classes comporte 6 concepts : classe, attribut, identifiant, relation, opération, généralisation/spécialisation. Ce diagramme est constitué des éléments suivants :

  • Classe : il s'agit de la description abstraite d'un ensemble d'objets : elle définit leurs structures, leurs comportements et leurs relations.
  • L'attribut : Il représente la modélisation d'une information élémentaire représentée par son nom et son format.
    UML définit 3 (trois) niveaux de visibilité pour les attributs :
    • Public (+) : l'élément est visible par tous les clients de la classe.
    • Protégé (#) : l'élément n'est visible que par les sous-classes ou les classes filles.
    • Privé (-) : l'élément n'est visible que par les objets de la classe auxquels il appartient.
  • L'identifiant : c'est un attribut particulier, qui permet de repérer de façon unique chaque objet, instance de la classe (Clé Primaire [PK]).
  • Multiplicité : elle définit le nombre d'instances de la classe, elle est définie par un nombre entier ou un intervalle de valeur (1..1, 0..1, 1..*, 0..*).
  • Associations : Une association est une relation entre deux classes (association binaire) ou plus (association n-aire), qui décrit les connexions structurelles entre leurs instances. Il existe plusieurs types de relations dont les plus connues sont les suivantes :
    • Généralisation : Relation d'héritage, dans laquelle les objets de l'élément spécialisé (Classe enfant) peuvent remplacer les objets de l'élément général (Classe parent).
    • Agrégation : utilisé pour les relations de types « contenant / contenu ».
    • La composition : La composition est un cas particulier de l'agrégation dans laquelle la vie des composants est liée à celle des agrégats (destruction en cascade).

Dictionnaire des classes du projet VigilCore :

Classe Rôle et Description Fonctionnelle Relations & Héritage
User (Utilisateur) Classe mère abstraite gérant les comptes, les identifiants de connexion, l'authentification et les niveaux d'accès RBAC. Classe parente de Operateur et Administrateur (Généralisation).
Operateur Représente le personnel technique effectuant la supervision en temps réel des 20 services, l'inspection de la boîte noire et le test de crise. Hérite de User. Exécute ScenarioSimulation (1 → 0..*).
Administrateur Responsable de la conformité des SLA bancaires, de la certification des audits et de l'export des registres 12 colonnes. Hérite de User. Génère et certifie RapportAuditSla (1 → 0..*).
ServicePartenaire Modélise chacun des 20 services financiers et marchands surveillés (MoMo, Wave, Visa, Orange Money, etc.) avec son endpoint de santé et son taux de disponibilité. Associé à Incident (1 → 0..*). Cible de ScenarioSimulation (1 ← 0..*).
Incident Cœur transactionnel du système : enregistre chaque rupture de service, le statut de traitement (investigating → resolved), le calcul exact du MTTR et l'horodatage WAT. Concerne ServicePartenaire. Compose BoiteNoireDiagnostic et NotificationAlerte. Consolidé dans RapportAuditSla.
BoiteNoireDiagnostic Encapsule les données forensiques complètes (payload brut JSON, code HTTP 500/504, cause racine, serveur hôte, endpoints API affectés). Composition forte avec Incident (1 ↔ 1, détruit avec l'incident).
NotificationAlerte Gère la diffusion multi-canal (Bot WhatsApp, Statuspage publique) et le statut de délivrabilité des alertes de crise. Composition avec Incident (1 → 0..*).
RapportAuditSla Produit le registre certifié des 12 colonnes techniques opposables aux banques et génère les fiches de reporting périodique en PDF Paysage. Consolide les Incident (1 ← 0..*). Généré par Administrateur.
ScenarioSimulation Fournit le catalogue d'injection de fausses pannes pour entraîner les équipes et valider le temps de réaction automatique du pipeline d'alerte. Exécuté par Operateur. Cible un ServicePartenaire.

III. Diagramme de déploiement

Le diagramme de déploiement est une vue statique qui sert à représenter l'utilisation de l'infrastructure physique par le système. Et la manière dont les composants du système sont répartis ainsi que les relations entre eux.

Le formalisme est le suivant :

FORMALISME DU DIAGRAMME DE DÉPLOIEMENT
Élément Description Représentation
Les composants Il représente une entité logicielle du système (Fichier de code source, programmes, documents, fichiers de ressource, etc.). Un composant est représenté par une boîte rectangulaire avec deux rectangles dépassant du côté gauche portant le nom du composant.
Les nœuds Un nœud représente un ensemble d'éléments matériels du système. Cette entité est représentée par un cube tridimensionnel.
Les Associations Une association, représentée par une ligne pleine entre deux nœuds, indique une ligne de communication entre les éléments matériels (avec protocole).
Les dépendances Une dépendance est utilisée pour modéliser la relation entre deux composants. La notation utilisée pour cette relation de dépendance est une flèche de pointillés.

Ce diagramme de déploiement unifié représente l'intégralité de l'infrastructure physique et logicielle du système VigilCore. Il illustre l'agencement des nœuds de traitement :

  • Poste Client (<<device>>) : Accès opérateur et auditeur via navigateur web moderne (Livewire / Alpine.js) et consultation des rapports signés.
  • Serveur Web & Sécurité NGINX (<<device>>) : Reverse proxy, déchargement SSL (TLS 1.3), pare-feu applicatif (WAF) et protection anti-abus.
  • Serveur d'Application Laravel 11 / PHP 8.2 (<<execution environment>>) : Cœur métier intégrant la gestion des pannes, le diagnostic, les tests des 20 services (toutes les 30s), le générateur Excel 12 colonnes et les tâches en arrière-plan.
  • Serveur de Données, Cache & Archivage (<<device>>) : Base relationnelle PostgreSQL 16 (port 5432), cache Redis (port 6379) et historique sécurisé des preuves scellées SHA-256.
  • Serveur d'Envoi d'Alertes n8n Node.js (<<execution environment>>) : Moteur de scénarios dédié à l'envoi immédiat des alertes WhatsApp et à la mise à jour de la page publique.
  • Passerelles Externes & Services Cloud (<<cloud>>) : Connexions sécurisées vers les 20 services partenaires de paiement (MoMo, Wave, Visa...) et les services Meta WhatsApp & Page Publique.

Dictionnaire des Nœuds d'Infrastructure & Protocoles

Nœud / Équipement Rôle & Composants Embarqués Liaisons & Protocoles Réseau
Poste Client Poste de travail opérateur / auditeur avec interface Livewire réactive et lecteur PDF/Excel. HTTPS (Port 443) vers le serveur frontal NGINX avec chiffrement TLS 1.3.
Serveur NGINX Reverse Proxy, terminaison SSL, compression gzip et pare-feu WAF anti-brute force. FastCGI (Port 9000) vers le socket PHP-FPM du serveur Laravel 11.
Serveur Laravel 11 Moteur applicatif VigilCore : état d'incident, boîte noire forensique, sondes 30s, constructeur 12 colonnes. TCP/IP vers PostgreSQL (5432), Redis (6379), REST Webhook vers n8n et HTTP/HTTPS vers passerelles.
Serveur Données & Cache PostgreSQL 16 (persistance relationnelle), Redis 7 (cache mémoire) et stockage forensique WORM. Port PostgreSQL 5432 et Port Redis 6379 restreints au sous-réseau applicatif privé.
Serveur n8n Orchestration des flux d'urgence : routage des alertes WhatsApp et publication sur Statuspage. HTTPS REST vers Evolution API (Docker / Baileys).0 et Atlassian Statuspage API.
Passerelles Tiers 20 passerelles de paiement bancaires et Mobile Money (MoMo, Wave, Visa, etc.). Interrogées toutes les 30 secondes par sondes HTTP/HTTPS avec timeout de 5 secondes.
